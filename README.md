# Plot Twist — 나무집 포트폴리오

현관에서 문손잡이를 누르고 나무집 방에 들어와, 물건에 다가가며 프로젝트와 관심사를 발견하는 사이트예요. 방문자 화면은 영어, 관리자 화면은 한국어예요. `Plot Twist`는 임시 이름이라 관리자 화면에서 바꿀 수 있어요.

## 켜기

Node.js 20 이상만 있으면 돼요. 따로 설치할 패키지는 없어요.

```bash
npm start
```

- 사이트: http://localhost:4173
- 관리자: http://localhost:4173/admin (비밀번호 변경은 `npm run set-password`)

## 주소

| 주소 | 내용 |
|---|---|
| `/` | 항상 현관부터 시작해요 |
| `/room` | 현관 없이 방으로 바로 들어가요 |
| `/w/공유주소` | 작품 상세로 바로 가요. 예: `/w/gachitayong`. `Explore the room`으로 방에 들어가요 |
| `/admin` | 관리자 화면 |
| `/preview/노션페이지ID` | 발행 전 노션 버전 미리보기 (관리자만) |
| `/?debug` | 클릭 영역을 색으로 표시해요 (개발용) |

## 둘러보는 순서

1. **현관:** 문손잡이(`Enter`)를 누르면 문이 열리고 방에 들어가요. 파란 우편함(`How to reach me`)에는 이메일 라벨이, 현판(`Who am I?`)에는 뒷면 소개가 있어요.
2. **방 전체:** 책상, 벽면, 휴식 구역 중 하나를 누르면 그쪽으로 줌인돼요.
3. **구역 안:** 물건 옆에 카테고리 이름이 떠요. 물건에 올리거나 탭하면 하위 분류와 이동 버튼이 보여요.
4. **카테고리 화면:** 왼쪽은 하위 분류 필터, 오른쪽은 그 물건을 테마로 한 배경이에요. 필터를 바꿔도 항목은 원래 자리에 남아요.
5. **`← Back`:** 바로 직전 상태로 돌아가요. 브라우저 뒤로 가기도 같아요.

## 그림과 클릭 영역

- 배경 그림은 `public/img/`에 있어요.
  - `porch.png`, `room.png`: 현관과 방이에요. 둘 다 1586×992예요.
  - `tabs/*.jpg`: 카테고리 화면 배경 아홉 장이에요.
  - 그 밖의 파일은 움직임에 쓰는 조각이에요.
- 패키지에서 다시 뽑으려면 아래 명령을 실행하세요.

  ```bash
  python3 tools/extract_assets.py "<Treehouse_Claude_Package/images 경로>"
  ```
- 클릭 영역, 카메라 이동, 카테고리 화면의 항목 자리는 모두 **원본 그림의 픽셀 좌표**로 `public/app.js`에 적혀 있어요. 방은 `ROOM`, 현관은 `PORCH`, 카테고리 화면은 `LAYOUTS`예요.
- 추가로 필요한 그림은 [docs/image-requests/README.md](docs/image-requests/README.md)에 정리돼 있어요.

## 관리자 화면에서 하는 일

**콘텐츠 탭**
- 항목을 추가·수정하고, 카테고리·하위 분류·공개 여부·대표 항목을 정해요.
- 대표 이미지를 올리면 목록용 작은 썸네일도 자동으로 만들어져요.
- 작곡 카테고리 항목에는 음원을 올려요.
- 진행 기록, 비공개 메모, 원본 첨부자료는 비공개 보관함에 넣어요. 방문자는 공개 목록, 공유 주소, 파일 주소 어디로도 이 자료를 열 수 없어요.

**카테고리 탭:** 카테고리 이름, 이동 버튼 문구, 하위 분류를 영어로 바꾸거나 추가해요.

**사이트 설정 탭**

| 설정 | 비워 두면 |
|---|---|
| 사이트 이름 | 비울 수 없어요. 탭 제목, 문패, 현판 뒷면에 함께 쓰여요. |
| 자기소개, 주요 이력 | 현판이 눌리지 않아요. |
| 이메일 | 우편함이 눌리지 않아요. |
| 네이버 블로그, 인스타그램 주소 | 액자가 눌리지 않아요. |
| 턴테이블 대표곡 | 음원이 있는 첫 공개 곡을 써요. 곡이 없으면 재생 버튼이 나타나지 않아요. |

## 배포 (정적 사이트 · 무료)

실제 사이트는 **Cloudflare Pages**의 정적 사이트예요. 서버가 없어요.

```
노션 ──(10분마다 GitHub Actions: scripts/sync.js)──▶ content/ (발행된 공개본, 저장소에 저장)
content/ ──(저장소에 올라가면 Cloudflare: npm run build)──▶ dist/ ──▶ 방문자
```

- `content/`: 발행된 공개본만 있어요 (글 `db.json`, 이미지 `uploads/`). 저장소에 올라가요. 비공개 메모·진행 기록·첨부는 넣지 않아요.
- `data/`: 이 Mac의 로컬 서버(`npm start`)가 쓰는 데이터예요. 저장소에 올라가지 않아요.
- `npm run build`: `content/`로 `dist/`에 정적 사이트를 만들어요. `npm run serve:static`으로 Cloudflare처럼 띄워 볼 수 있어요.
- `.github/workflows/notion-sync.yml`: 10분마다 노션 요청을 반영하고, 바뀌었으면 저장소에 올린 뒤 노션에 '발행됨'을 적어요. 급하면 GitHub 저장소 → Actions → Notion sync → **Run workflow**.
- GitHub 저장소 설정: Settings → Secrets and variables → Actions
  - Secrets에 `NOTION_TOKEN`
  - (선택) Variables에 `NOTION_SETTINGS_DS` (노션 '사이트 설정' DB의 data_source_id)
- Cloudflare Pages 설정: 빌드 명령 `npm run build`, 출력 폴더 `dist`
- 공개 저장소는 60일 동안 변화가 없으면 예약 실행이 멈춰서, 워크플로가 45일마다 빈 기록을 남겨요.
- 정적 사이트에는 관리자 화면(`/admin`)이 없어요. 미리보기는 이 Mac에서 `npm start` 후 관리자 화면 노션 탭을 써요.

## 노션 연동

작품과 분류는 노션에서 관리해요. 사이트는 노션의 `전시 게시물`과 `분류 관리` 두 DB만 읽어요. `작업물` DB(내부 기록, 일정, 원본 자료)는 읽지 않고, 동기화할 때 AI도 부르지 않아요.

### 켜는 법
1. 노션에서 통합(Integration)을 만들어요. 권한은 '콘텐츠 읽기'와 '콘텐츠 업데이트'예요.
2. `전시 게시물`과 `분류 관리`에만 그 통합을 연결해요. `작업물`과 상위 페이지에는 연결하지 않아요.
3. 프로젝트 폴더에 `.env` 파일을 만들고 토큰을 한 줄 넣어요. 이 파일은 서버만 읽고 저장소에 올라가지 않아요(`.gitignore`).

   ```
   NOTION_TOKEN=노션에서_받은_토큰
   ```
4. 서버를 다시 켜면 관리자 화면 `노션` 탭에 '연결됨'이 보여요. 로컬 서버는 기본적으로 **미리보기 전용**이에요. 발행은 GitHub Actions가 해요(두 곳에서 동시에 발행하지 않게).

| 환경변수 | 기본값 | 뜻 |
|---|---|---|
| `NOTION_TOKEN` | 없음 | 없으면 연동이 꺼지고 사이트는 지금 데이터로 그대로 돌아가요 |
| `NOTION_LOCAL_PUBLISH` | 꺼짐 | `1`이면 로컬 서버도 발행해요 (서버로 운영할 때만) |
| `NOTION_SYNC_MINUTES` | 5 | 로컬 서버가 발행할 때 몇 분마다 확인할지 |
| `NOTION_SETTINGS_DS` | 없음 | 노션 '사이트 설정' DB(항목·값)를 쓸 때 |
| `NOTION_SHOWCASE_DS`, `NOTION_CATEGORY_DS` | 연결된 DB의 data_source_id | 다른 DB로 바꿀 때만 써요 |

### 발행하는 법
- `전시 게시물`의 `발행 상태`가 처리 기준이에요.

| 노션 상태 | 사이트 |
|---|---|
| 초안, 검토 중, 수정 중, 발행됨 | 아무것도 바꾸지 않아요. 노션을 고쳐도 기존 공개본이 그대로 보여요 |
| 발행 요청, 재발행 요청 | 그 순간의 글과 이미지를 `content/`로 복사해 공개본을 한 번에 바꿔요. 사이트에 반영되면 노션에 `발행됨`, 사이트 ID, 발행일, 버전을 적어요 |
| 내림 요청 | 비공개로 돌려요. 공유 주소와 파일 주소도 열리지 않아요. 노션에는 `내려감`을 적어요 |

- 재발행해도 작품 주소와 최초 발행일은 그대로예요. 첫 발행 뒤에는 작품 주소를 바꿀 수 없어요.
- 이미지 하나라도 받지 못하거나 값이 틀리면 발행하지 않고, 기존 공개본을 그대로 둬요. 원인은 노션 `발행 메모`와 관리자 화면 `노션` 탭의 '최근 기록'에 남아요. 고치면 다음 동기화 때 다시 시도해요.
- 같은 요청을 여러 번 실행해도 노션 페이지마다 작품 하나만 있어서 카드가 늘지 않아요.
- 관리자 화면 `노션` 탭의 `미리보기`는 아직 발행하지 않은 노션 버전을 보여줘요. 로그인한 관리자에게만 열려요(`/preview/<노션 페이지 ID>`).
- 노션에서 발행한 작품은 관리자 화면에서 공개 내용을 고칠 수 없어요. 비공개 메모, 진행 기록, 첨부자료만 고칠 수 있어요.
- 노션 `상세 요약`은 아직 사이트에 쓰지 않아요.
- 점검: `npm run test:notion`(서버 방식 55개), `npm run test:static`(정적 사이트 방식 20개). 둘 다 가짜 노션과 빈 테스트 폴더만 써요.

### 분류
- 이름, 순서, 방 물건 연결, 사용 여부는 동기화할 때마다 노션 `분류 관리`를 따라요. 화면에는 `영어 이름`이 보이고, 비어 있으면 `이름`을 써요.
- 상위 분류는 `사용`이 켜져 있고 방 물건이 연결돼 있을 때만 보여요. 새 상위 분류는 연결한 방 물건의 화면 배경과 칸 배치를 빌려 써요.
- 하위 분류는 공개 작품이 있을 때만 필터에 보여요.
- 노션에서 지운 분류는 사이트에서도 지우지 않고 숨겨요. 작품 연결이 끊기지 않게 하려는 거예요.

## 파일 구조

- `server.js`: 서버예요. 공개 규칙, 관리자 API, 파일 보호를 맡아요.
- `lib/store.js`: 데이터를 저장해요. 기본값과 예전 데이터 변환도 여기 있어요.
- `lib/notion.js`, `lib/notion-sync.js`: 노션 읽기와 발행 동기화예요.
- `public/app.js`, `public/styles.css`: 방문자 화면이에요.
- `public/admin/`: 관리자 화면이에요.
- `data/`: 실제 콘텐츠와 올린 파일이 들어 있어요. **백업할 곳은 이 폴더 하나예요.**
- `docs/handover/`: 노션 연동 인수인계서(PDF)와 그 원본 HTML이에요. HTML을 고친 뒤 크롬에서 PDF로 저장하면 돼요.
- `tests/notion/`: 가짜 노션으로 발행 흐름 전체를 점검해요. `npm run test:notion`
- `docs/image-requests/`: 추가 그림 요청서와 위치 표시 이미지예요.
- `docs/previews/`: 데스크톱·모바일·추가 동작 프리뷰예요. 브라우저로 열어 보세요. 테스트 데이터로 녹화했어요.
- `tools/extract_assets.py`: 패키지 그림에서 사이트용 조각을 만들어요.
